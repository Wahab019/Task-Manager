Architecture Overview

1. Data Persistence (SQLite)
All tasks and timelogs are persisted locally in SQLite (`data/taskmanager.sqlite`) managed by `src/lib/db.ts`. Prepared statements handle all CRUD operations with transactions and WAL concurrency.

2. User Authentication (Appwrite Auth)
User identity and authentication are managed through Appwrite Cloud. The frontend (`src/lib/appwrite.ts`) creates sessions and issues JWTs. API routes (`/api/tasks`, `/api/timelogs`) authenticate requests via `src/lib/auth.ts`, extracting the Bearer token and verifying the user identity with Appwrite's Account API before querying SQLite scoped to `user.authUserId`.

3. Next.js 16 Request Proxy
Next.js 16 proxy convention (`src/proxy.ts`, formerly `middleware.ts`) intercepts requests to redirect authenticated users to `/dashboard` and unauthenticated users to `/login`.

4. State Management (React Context)
- `AuthContext` (`src/context/AuthContext.tsx`): Tracks logged-in user profile, loading state, and logout actions.
- `SidebarContext` (`src/context/SidebarContext.tsx`): Coordinates navigation sidebar toggle and mobile responsiveness.
- `TimerContext` (`src/context/TimerContext.tsx`): Central state store for live task tracking, running timer intervals, active task selection, optimistic task creation/updating, and server synchronization.

5. Data Transfer Layer
`src/app/api/tasks/response.ts` defines the `TaskResponse` DTO and maps database records (`TaskRecord`) to the standardized frontend contract, decoupling SQLite schema from frontend views.
